**You don't need to be a developer.** If you can edit a text file and follow a recipe, you can run this site.

## 1. What this site is

The BSidesFrankfurt website is a **static site** generated by [Hugo](https://gohugo.io/). That means:

- **No backend, no database, no logins.** Hugo turns a folder of Markdown and YAML files into plain HTML.
- **You edit files; Hugo rebuilds.** You make a change, save, and the site updates within a second.
- **Deployment is just uploading a folder.** Currently hosted on Cloudflare Pages.

The site you're editing lives at **`hugo-site/`** inside the repository.

---

## 2. Glossary (read this first)

| Word | What it means here |
|------|--------------------|
| **Markdown (`.md`)** | A simple text format with headings, links, and lists. The kind of file blog posts are written in. |
| **YAML (`.yaml`)** | A simple key-value text format for structured data (sponsors, team, FAQ). Indentation matters! |
| **Frontmatter** | The block of YAML at the top of a Markdown file (between two `---` lines) that holds metadata like title and date. |
| **Partial** | A small reusable HTML template (the navigation bar, the footer). You usually won't edit these. |
| **Layout** | A bigger HTML template that defines a full page (the homepage, a blog post page). |
| **Data file** | A YAML file under `data/` that holds structured info read by layouts. Edit these often. |
| **Content file** | A Markdown file under `content/` that becomes a page on the site. Edit these often. |
| **Static file** | Anything under `static/` is copied verbatim to the site root (images, fonts, the favicon). |

## 3. One-time setup

### What you'll need

- A computer running macOS, Linux, or Windows
- A code editor — [VS Code](https://code.visualstudio.com/) is free and friendly
- [Git](https://git-scm.com/) (often pre-installed)
- [Hugo](https://gohugo.io/) **extended edition**

### Install Hugo

**macOS** (Homebrew):
```sh
brew install hugo
```

**Linux** (Debian/Ubuntu):
```sh
sudo snap install hugo
```

**Windows** (Chocolatey or Scoop):
```sh
choco install hugo-extended
# or
scoop install hugo-extended
```

Verify the install — you should see `extended` in the version string:
```sh
hugo version
# → hugo v0.160.x+extended ...
```

### Clone the repository

```sh
git clone <REPO_URL>
cd <REPO_FOLDER>/hugo-site
```

You should now see folders called `content/`, `data/`, `layouts/`, `static/`, etc.

### Run the site locally

```sh
hugo server
```

Open [http://localhost:1313](http://localhost:1313) in your browser. **Keep `hugo server` running** while you edit — every save reloads the page automatically.

To stop, press `Ctrl+C`.

## 4. Daily workflow

1. **Pull the latest changes** before you start editing:
   ```sh
   git pull
   ```
2. **Start the local preview**:
   ```sh
   cd hugo-site
   hugo server
   ```
3. **Edit a file** (recipes below). Save. Watch the browser refresh.
4. **Commit your changes** when happy:
   ```sh
   git add .
   git commit -m "Add new sponsor: Acme Security"
   git push
   ```
5. **Deploy** (see [section 8](#8-building-and-deploying)).

## 5. Editing recipes

Each recipe says *which file to open* and *what to change*. Copy the example into the file, swap the values, save.

### 5.1 Change event dates / venue / social links

**File:** `data/event.yaml`

```yaml
name: BSidesFrankfurt
year: 2026
dates:
  conference: 2026-09-10
  workshops: 2026-09-11
  display: "10–11 September 2026"     # ← human-readable, shown in hero
location:
  name: Goethe University Frankfurt
  address: "Theodor-W.-Adorno-Platz 1, 60323 Frankfurt am Main"
  mapUrl: "https://www.uni-frankfurt.de/..."
social:
  twitter: "https://x.com/BSidesFRA"
  instagram: "https://instagram.com/BSidesFRA"
  mastodon: "https://infosec.exchange/@bsidesfra"
  linkedin: "https://www.linkedin.com/company/bsides-frankfurt/"
  email: "info@bsidesfrankfurt.org"
```

This file feeds the **hero**, **footer social icons**, and **contact email** across every page.

---

### 5.2 Add or remove sponsors

**File:** `data/sponsors.yaml`

The file has three tiers: **gold**, **silver**, and **partners**. Each entry has a name, logo path, and URL.

#### Add a sponsor

1. Save the logo into `static/images/sponsors/` (SVG preferred; transparent PNG also fine).
2. Open `data/sponsors.yaml` and add a new entry under the right tier:

```yaml
gold:
  - name: "Acme Security"
    logo: "/images/sponsors/acme-security.svg"
    url: "https://acmesecurity.example/"

silver:
  - name: "Existing Silver Sponsor"
    logo: "/images/sponsors/existing.svg"
    url: "https://existing.example/"
  - name: "New Silver Sponsor"           # ← new entry
    logo: "/images/sponsors/new.svg"
    url: "https://new.example/"
```

#### Remove a sponsor

Delete the four lines for that sponsor (`- name`, `logo`, `url`, plus the indentation line). Save.

#### Notes

- Logos automatically appear greyscale, then turn full-colour on hover.
- Tier order on the page: **Gold → Silver → Partners**.
- Logos must be `/images/sponsors/<filename>` — note the leading slash.

### 5.3 Add or remove team members

**File:** `data/team.yaml`

Two sections: `organisers` (lead organisers — usually 2-3 people, shown larger) and `team` (the rest of the volunteers).

```yaml
organisers:
  - name: "Alexander Georgiev"
    role: "Lead Organiser"
    image: "/images/teammember_1.png.webp"
    linkedin: "https://www.linkedin.com/in/alexander-georgiev-93610038/"
    twitter: "https://x.com/mechpen"          # optional
  - name: "Hristiyan Lazarov"
    role: "Lead Organiser"
    image: "/images/teammember_2.png.webp"
    linkedin: "https://www.linkedin.com/in/hlazarov/"

team:
  - name: "New Volunteer"
    role: "Organising Team"
    image: "/images/teammember_X.png.webp"
    linkedin: "https://www.linkedin.com/in/..."     # optional
```

#### Adding a person

1. Save their photo into `static/images/` (square, ~400×400 PNG/JPG/WebP).
2. Add a new block under `team:` (or `organisers:` if they're a lead).
3. `linkedin` and `twitter` are optional — omit the line if no profile.

#### Removing a person

Delete the block for that person (the `- name:` line and everything indented under it).

### 5.4 Edit the FAQ

**File:** `data/faq.yaml`

A flat list of question/answer pairs. The answer supports Markdown (you can use `[link text](url)` and `**bold**`).

```yaml
- question: "Will the talks be recorded?"
  answer: "We aim to record most of the main-track talks and publish them after the conference, subject to speaker consent."

- question: "Is the venue accessible?"
  answer: "Yes. Goethe University Frankfurt's Westend Campus is fully wheelchair-accessible. Email info@bsidesfrankfurt.org for specific needs."
```

To add a question, add a new `- question: "..."` block at the bottom. Order in the file = order on the page.

### 5.5 Edit the "What is BSides?" cards

**File:** `data/about.yaml`

The two cards on the homepage. Each has an icon, title, and description.

```yaml
- id: community
  icon: "fas fa-users"           # any Font Awesome 6 icon
  title: Community
  description: >-
    BSidesFrankfurt is organized by the community, for the community...

- id: technical
  icon: "fas fa-terminal"
  title: Technical
  description: >-
    We focus solely on technical content. No vendor pitches...
```

Find Font Awesome icons at [fontawesome.com/search](https://fontawesome.com/search?o=r&m=free).

### 5.6 Add a blog post

1. Create a new file: `content/blog/your-slug.md` — the slug becomes the URL.
2. Paste this template at the top, then write the article body in Markdown:

```markdown
---
title: "Your post title"
date: 2026-05-01
author: "Your name"
summary: "One-sentence description shown on the blog index and in homepage previews."
tags: ["community", "cfp"]
draft: false
---

Article body in **Markdown**. Use headings, [links](https://example.com),
lists, code blocks — anything Markdown supports.

## Section heading

More text.

> Block quotes look good too.
```

#### Notes

- **`draft: true`** hides the post unless you run `hugo server -D`.
- Posts are sorted newest-first on `/blog/`.
- Images for a post: drop them in `static/images/blog/` and use `/images/blog/your-image.png` in the post.

#### Remove a blog post

Delete the `.md` file. Done.

### 5.7 Add an announcement

Announcements are small updates that surface on the homepage (latest 3) and on the dedicated `/announcements/` page.

1. Create `content/announcements/short-slug.md`.
2. Use this template:

```markdown
---
title: "Ticket sales now open"
date: 2026-04-22
tag: "Tickets"                 # short label shown before the date on the homepage
summary: "One-sentence preview shown in the announcement card."
draft: false
---

Optional longer body in Markdown for the dedicated page.
```

The three most recent announcements appear on the homepage automatically.

### 5.10 Add or change navigation menu items

**File:** `hugo.toml`

The `[menu]` section controls the top-bar menu.

```toml
[[menu.main]]
  name = "Schedule"          # label shown in the bar
  url = "/schedule/"          # internal link (or absolute https://...)
  weight = 20                 # lower number = further left
```

For dropdown menus (like Archive):

```toml
[[menu.main]]
  name = "Archive"
  identifier = "archive"      # parent must have an identifier
  weight = 80

[[menu.main]]
  parent = "archive"          # links into "archive"
  name = "2025"
  url = "https://2025.bsidesfrankfurt.org"
  weight = 10
```

The right-hand CTA buttons (Tickets / CFP) are in a separate block:

```toml
[[menu.cta]]
  name = "Tickets"
  url = "https://tickets.bsidesfrankfurt.org/bsidesfrankfurt/2026/"
  weight = 10
```

### 5.11 Add speakers (when ready)

**File:** `data/speakers.yaml` already exists with placeholder data. The carousel partial and CSS are still in place — they're just not currently shown on the homepage (the section was removed pending speaker confirmation).

**To show speakers again on the homepage**, edit `layouts/index.html` and add this block where you want them:

```html
<section>
  <div class="container">
    <div class="mb-5" style="display: flex; justify-content: space-between; align-items: end; flex-wrap: wrap; gap: var(--space-3);">
      <div>
        <span class="eyebrow">Lineup</span>
        <h2 class="section-title" style="margin: 0;">Featured Speakers</h2>
      </div>
      <a href="{{ "/schedule/" | relURL }}" class="btn btn--sm btn--outline">Full schedule →</a>
    </div>
    {{ partial "speakers-carousel.html" . }}
  </div>
</section>
```

Then edit `data/speakers.yaml`:

```yaml
- name: "Real Speaker Name"
  photo: "/images/speakers/real-speaker.jpg"   # leave "" for an auto-initials avatar
  role: "Their job title and company"
  bio: "Short 1–2 sentence bio. Will be truncated to 3 lines on the card."
  linkedin: "https://www.linkedin.com/in/..."   # optional
  talk: "Title of their talk"
```

## 6. Images and other assets

Anything under **`static/`** is copied verbatim to the website's root. So:

| Where you save it | URL on the site |
|-------------------|-----------------|
| `static/images/sponsors/acme.svg` | `/images/sponsors/acme.svg` |
| `static/images/blog/photo.jpg` | `/images/blog/photo.jpg` |
| `static/files/programme.pdf` | `/files/programme.pdf` |

**Don't** put `static/` in the URL — Hugo strips it automatically.

#### File-naming tips

- No spaces (use hyphens or underscores)
- Lowercase
- Keep file size sensible: SVG/WebP for logos, JPG (compressed) for photos
- Square photos for team/speakers (they're displayed in circles)

## 7. Changing colors and fonts

**File:** `assets/css/main.css`, very top of the file.

```css
:root {
  --color-bg:      #011023;     /* dark blue page background */
  --color-surface: #121314;     /* card background */
  --color-primary: #9acd32;     /* yellowgreen — buttons, accents */
  --color-secondary:#eb3812;    /* reddish-orange — hover states */
  --color-text:    #ffffff;
  --font-heading:  'Poppins', sans-serif;
  --font-body:     'Open Sans', sans-serif;
}
```

Change a variable, save — every component picks it up. **Don't** edit individual component colors; change the variable.

## 8. Building and deploying

### Build for production

```sh
cd hugo-site
hugo --minify
```

The output appears in `hugo-site/public/`. That folder is what gets uploaded to the host.

### Deploy to Cloudflare Pages (current host)

#### Option 1 — Dashboard (simplest)

1. Build the site (`hugo --minify`).
2. Zip the `public/` folder.
3. Go to Cloudflare Dashboard → Workers & Pages → your project → **Create deployment** → **Upload assets**.
4. Drag the zip in and click **Deploy**.

#### Option 2 — Wrangler CLI (faster on repeat)

```sh
npm install -g wrangler          # one-time
wrangler login                    # one-time
cd hugo-site
wrangler pages deploy public --project-name=bsidesfrankfurt
```

### Custom domain

Point `bsidesfrankfurt.org` at the Cloudflare Pages project in the Cloudflare dashboard → Pages → Custom domains.

## 9. Subdomain archive (2023/2024/2025)

Each past edition lives at its own subdomain:

- `2023.bsidesfrankfurt.org`
- `2024.bsidesfrankfurt.org`
- `2025.bsidesfrankfurt.org`

These are **separate sites** — typically uploaded as static archives of the year's website at the time. The main site links to them in the **Archive** dropdown ([hugo.toml](hugo.toml) `[menu.main]` block).

To set one up:

1. Take a snapshot of the year's content (e.g. the `2025/` folder from the original repo).
2. Upload that folder to a new Cloudflare Pages project.
3. In Cloudflare Pages → Custom domains, add `2025.bsidesfrankfurt.org`.
4. Update DNS so the subdomain points at the project.

You don't need Hugo for these — they're frozen in time.

## 11. Troubleshooting

**"My changes don't show up."**
Make sure `hugo server` is running and the browser is pointing at `http://localhost:1313`. If still stuck, stop with `Ctrl+C` and run `hugo server` again.

**"YAML error: mapping values not allowed."**
Indentation problem. YAML uses spaces (no tabs). Check that all sub-items under a list entry are indented the same.

**"Image is missing on the page."**
Check the path. URLs that begin with `/images/...` correspond to `static/images/...` on disk. Don't include `static/` in the URL itself.

**"Build fails with `taxonomy` warning."**
Harmless — we don't use tag-list pages. Site builds fine despite the warning.

**"Site looks broken on mobile."**
Force-refresh with `Ctrl+Shift+R` (or `Cmd+Shift+R`). Phone-style preview is built into Chrome DevTools (`F12` → click device-toolbar icon).

**"I broke something and want to undo."**
```sh
git status                      # see what changed
git checkout -- <filename>      # revert one file
git checkout -- .               # revert everything (careful)
```

**"Favicon won't update in Chrome."**
Chrome caches favicons aggressively. Try an Incognito window — that's the fastest way to verify.

**"`hugo` says non-extended."**
Reinstall with the extended variant. On macOS, `brew install hugo` already gives you extended. On other platforms, look for `hugo_extended` in the package name.
